# Cue prototype: status

Branch `feature/cue-prototype`. Scope: Phases 1–4, plus Phase 5 because 1–4 went green first. Phase 6 (iPhone Duo) and Phase 7 (Watch, full accessibility pass) are waiting on you, as agreed.

## How it was built and checked

This was built remotely, without a Mac. Everything below compiles and passes tests in GitHub Actions on **Xcode 26.6 with the iOS 26.5 SDK**. The runners don't have the iOS 27 SDK yet, which is why the target is iOS 26.0.

| Check | Where | Result |
|---|---|---|
| CueCore unit tests: 50 tests covering the parser, scanner, read time, alignment with messy transcripts, filler counter, coach, scroll spring and word diff | Linux, Swift 6.2, warnings as errors | ✅ |
| App unit tests: 21 tests covering the prompter view model, sample data, importer, settings decoding, lens placement and polish | iPhone 17 Pro Max simulator, iOS 26.5, Swift 6 strict concurrency, warnings as errors | ✅ |
| UI test: create a script → prompter play/pause → record a take (simulated camera) → coach card | Same simulator | ✅ |
| Committed `Cue.xcodeproj` matches `project.yml` | Linux, XcodeGen built from a pinned commit | ✅ |

**Keeping the project in sync.** `Cue.xcodeproj` is generated by XcodeGen from `project.yml` and committed, so you can open it with nothing installed. XcodeGen is built from source at a pinned commit (`783a19e`, the same one used here). CI regenerates the project on every push and fails if the result differs from what's committed. If you edit `project.yml`, run `xcodegen generate` (`brew install xcodegen`) and commit both files. If you add files in Xcode instead, also add them under `project.yml`'s source folders, which already happens automatically for anything inside `App/`, `Tests/` or `UITests/`, and regenerate.

**Nothing has run on a real iPhone yet.** The camera, microphone, speech model and Foundation Models only work on hardware, so those paths compile but are unproven until your day-one test (see TESTING.md).

## Done

**Phase 1: Foundation**
- SwiftData models (`Script`, `ScriptFolder`, `Take`, `PrompterPreset`), built so CloudKit can be added later. Three sample scripts are seeded on first launch, one of which uses every markup tag.
- Library with folders, search, sort by last edited or title, swipe actions (delete, duplicate, open prompter), a context menu to move scripts between folders, and empty states.
- Import of .txt, .md and .rtf from Files, plus "Open in Cue" from other apps.
- Editor with live markup highlighting, a keyboard toolbar for inserting markup, and a live read time with a per-script pace (default 140 wpm).
- Design tokens with your refinements: Mist-light, Tungsten-deep and `#ECEDEF` stage text. Every token has Increase Contrast variants.

**Phase 2: Prompter**
- Driven by `CADisplayLink` at up to 120 Hz, with no `Timer`.
- Reading-line glow band. With Increase Contrast it switches to a solid rule; with Reduce Motion it doesn't animate.
- Display controls: font size, line spacing, margins, alignment, speed, mirror, reading-line position, typeface (SF Pro or New York) and countdown.
- Presets: Rig mode, Selfie mode and Rehearsal are built in, and you can save your own.
- 3-second countdown with haptics; tap to pause; double-tap for the next section; two-finger drag to scrub.
- The controls auto-hide after 2 seconds while scrolling.
- Keyboard and clicker keys: Space and Return play or pause, the arrows and Page Up/Down move between sections, and Up/Down change speed.

**Phase 3: Recording**
- Front or rear camera. Resolution and frame rate offer only what the device supports, and you can choose an external mic.
- Recording goes through `AVAssetWriter`. The script overlay is SwiftUI on top of the preview, so it's never in the video.
- The script panel sits near the lens: at the top in portrait, and on the camera side when an iPhone is in landscape.
- Takes library with thumbnails and playback, Export to Photos (add-only permission), share and delete.

**Phase 4: Voice pacing and the coach**
- `SpeechAnalyzer` + `SpeechTranscriber` (iOS 26), on device, with volatile results. If those aren't available it falls back to `SFSpeechRecognizer` with `requiresOnDeviceRecognition = true`.
- While recording, the movie and speech recognition share one microphone stream.
- `TranscriptAligner`: windowed fuzzy alignment that never moves backwards. It copes with skipped words, ad-libs and mispronunciations, and recovers when you skip a whole section.
- Spoken words dim. Scrolling waits when you stop and catches up on a spring with no overshoot.
- If the speech model is missing, permission is denied or the language isn't supported, the prompter shows a one-line message and scrolls at a steady speed. It never shows a dead screen.
- Delivery coach after each take: pace against your target, script coverage, longest pauses, off-script stretches by section, and filler words. Words like "like" only count when they aren't in your script.
- Debug screen (Settings → Debug tools, debug builds only): a fake-transcript player with pace and messiness controls, and **Reset sample data**.
- First-launch flow: your privacy wording, then each permission explained in one line before the system prompt. If you deny one, it offers Open Settings.

**Phase 5: AI polish**
- Make it sound spoken, Trim to N seconds, and Add pause marks, applied to the selected text or the whole script.
- Uses only `SystemLanguageModel.default` (on device), never cloud or Private Cloud Compute models. The feature is hidden when the model isn't available.
- Every suggestion appears as a word diff with before and after read times. You choose **Use this** or **Keep original**, and accepted changes can be undone.

## Stubbed or deferred

- **iPhone Duo (Phase 6):** nothing built. As agreed, I didn't build the rear-camera mode. Stand mode will become a manual "Stand layout" button once you've checked the Xcode 27.1 SDK for fold, posture and outer-display APIs. No Duo-specific API is referenced anywhere, so there's nothing to guard.
- **Apple Watch remote (Phase 7):** no watchOS target, as you asked. Keyboard and clicker control are done.
- **iCloud sync:** the toggle is in Settings and the models are ready for CloudKit. It stays disabled with an explanation until a container is set up. To set it up: add the iCloud capability with a CloudKit container in Xcode, and put the container ID in `project.yml` under `CueCloudKitContainer`. It applies at the next launch.
- **Share extension:** not built. Importing works through Files and through "Open in Cue" from other apps' share sheets.
- **Liquid Glass:** uses the system `glassEffect`, `.glass` and `.glassProminent` styles, which have only been seen in the Simulator.

## Known issues and risks

1. **Nothing has been tested on a device.** The capture pipeline (formats, rotation, mirroring, AVAssetWriter timing) and live speech have only been compiled. If something breaks on day one, it's most likely there.
2. **Mic sharing while recording.** The capture session configures the audio session itself. Bluetooth (HFP) mics aren't enabled on purpose; wired and USB mics should work.
3. **Countdown and recording.** The camera starts recording when you tap record, and the 3-2-1 countdown plays inside the take. Trim the start if you don't want it.
4. **iPad landscape** puts the script at the top edge, which is right for current iPads with the camera on the long edge. Older iPads with the camera on the short edge get the same layout.
5. **Accessibility** has the basics: Dynamic Type in the library and editor, VoiceOver labels and actions on the stage, Reduce Motion and Increase Contrast. The full audit is Phase 7.
6. **Unit tests run inside the live app.** CI shows harmless SwiftData first-launch logs from that.
7. **The TestFlight workflow** (`.github/workflows/testflight.yml`) has never run. It's manual only and skips cleanly without the four secrets. It needs an App Store Connect app record for the bundle ID you pass.
